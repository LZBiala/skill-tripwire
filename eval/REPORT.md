# skill-tripwire evaluation report

Regenerated by `python eval/run_eval.py`. CI fails the build if this file drifts
from what the code produces, so every number here is reproducible from a clone.

A detection rate alone is not published anywhere in this file. Each rate carries
its denominator, a rule-of-three bound where a count is zero, and - for the
headline - precision recomputed at the ~2% base rate the field measures.

## Detection on the self-authored corpus (NOT a generalization number)

- on samples the rules were built against: 7/7 = 100.0%. This is an upper bound and nothing more.
- on the author's own limit-probe set (written knowing the rules, each sample pre-labeled a designed catch or a designed miss): 3/8 = 37.5%.
- probes that miss, kept on the scorecard (each a real, named limit): ho-homoglyph-curl, ho-semantic-exfil-nourl, ho-capability-webfetch-drift, ho-structural-exfil, ho-cross-tool-shadow

Read that second line as a demonstration, not a measurement. The catches show the
canonicalize-and-decode pipeline defeats obfuscation; the misses document limits
the deterministic rules genuinely cannot reach (homoglyphs, no-token semantics,
cross-line dataflow, capability drift beyond shell). But the author picked the
samples, so the RATIO measures the author's imagination, not the tool's reach.

**The one number that would be a real measurement - detection on a corpus authored
by someone else (published third-party PoCs, another researcher's samples) - is not
yet computed. It is the top open item, and no home-made proxy is printed in its**
**place.** Substituting a self-authored set for it is the exact error this repo warns about.

## False positives (all benign samples, several chosen as probes)

- false positives: 0/18, so FPR <= 16.7% (rule of three)
- benign probes included: IMPORTANT phrasing, a narrow Bash grant, a matching WebFetch grant, a UUID, a credentials path, a benign base64 blob, a curl mention

## Precision at the measured ~2% marketplace base rate

- using the limit-probe recall and the FPR bound: 4.4%
- using the tuned upper-bound recall: 10.9%
(Both use self-authored recall, so read them as illustrations of the base-rate
effect, not as field precision.)

Read those twice. Even at the flattering recall, a scanner at a 2% base rate with
a realistic false-positive rate is mostly wrong when it alarms. That is the base-
rate fallacy (Axelsson), and it is why the noisy rules here route to REVIEW and
never hard-block, and why this small curated benign set will read cleaner than the
wild. FPR, not recall, is the number that decides whether anyone trusts the alarm.

## The ceiling, stated

These numbers are a floor measured on a small seeded corpus, not a guarantee.
Independent studies show static scanners lose 45-99% of findings under payload-
preserving obfuscation, and semantic attacks with no trigger token are out of
deterministic reach entirely (see the held-out misses above). skill-tripwire is a
triage layer; containment belongs to sandboxing and architecture.
